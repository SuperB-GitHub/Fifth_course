
# Генерация простых чисел, критерий примитивности и метод пробных делений

## Генерация простых чисел и решето Эратосфена

Любое простое число, кроме 2, нечётно. Для генерации простых чисел используют признаки делимости (на 3, 5, 9) для отсечения заведомо составных чисел, либо решето Эратосфена.

Решето Эратосфена приписывается древнегреческому учёному Эратосфену Киренскому (276–194 гг. до н.э.). Для нахождения всех простых до границы B выписывают последовательность нечётных чисел от 3 до B. Затем берут первое число (3), оставляют его и вычёркивают все кратные 3, начиная с 6. Переходят к следующему числу (5), вычёркивают кратные 5. Процесс продолжают до конца списка. Оставшиеся числа — простые.


## Теорема и критерий примитивности и проверки простоты

**Теорема (критерий примитивности и простоты).** Если для некоторых a и p выполнены условия:

1. a^(p−1) ≡ 1 (mod p),
2. a^((p−1)/q) ≢ 1 (mod p) для всех q | (p−1),

тогда число p — простое, а a является примитивным корнем поля GFp (генератором группы по умножению).

**Пример.** n = 1 022 333 835 329 657, n − 1 = 2 · 2957 · 146 063 · 292 877.
3^(n−1) ≡ 1 (mod n),
3^((n−1)/2) ≡ −1 (mod n),
3^((n−1)/2957) ≡ 324224767363906 (mod n),
3^((n−1)/146063) ≡ 697302646321792 (mod n),
3^((n−1)/292877) ≡ 736785752408036 (mod n).

Число n простое, а 3 — примитивный корень GFn. Однако разложение n−1 на множители само сложная задача, поэтому для длинных чисел критерий неприменим.



## Метод пробных делений

Метод пробных делений (trial division) — простейший метод проверки простоты числа n или нахождения его делителей. В цикле выполняется пробное деление n на все целые числа от 2 до ⌊√n⌋:

int Tr_div(int n) {
  for(int i = 2; i <= ⌊√n⌋; i++)
    if (n % i == 0) return i;
  return 0;
}

Каждое деление имеет сложность O(log₂n), общая сложность метода — O(n^(1/2)·log₂n). Через L = ⌊log₂n⌋ оценка записывается как T(n) = O(L² · e^(L/2)). Алгоритм имеет экспоненциальную оценку относительно длины входного числа, поэтому не применим для тестирования больших чисел.



# Обзор статьи: «Пора менять методы защиты»

## Введение

Статья посвящена проблеме перехода от классической криптографии к постквантовой. Автор напоминает: сегодня вся безопасность в сети — пароли, банковские карты, переписки — держится на криптографии. Мы привыкли думать, что это надёжно, потому что обычному компьютеру нужны тысячи лет, чтобы подобрать ключ. Но ситуация скоро изменится: появляются квантовые компьютеры, для которых сложные математические задачи — пустяк. Если не придумать новые способы защиты заранее, однажды все секреты мира могут быть раскрыты.

## Основная часть

Главная проблема в том, что квантовые компьютеры работают по другим законам физики. С помощью алгоритма Шора они могут мгновенно разломать современные цифровые замки. Что с этим делать? Математики предлагают использовать задачи, которые не под силу даже квантовому компьютеру. Самый перспективный вариант — криптография на решётках.

Если говорить просто, то мы прячем секрет в огромной многомерной паутине из точек. Чтобы найти правильную точку, нужно решить уравнение As + e = b, где A — матрица, s — секретный вектор, e — ошибка, b — правильная точка. Вектор e играет роль намеренно внесённого шума: даже небольшое отклонение делает невозможным использование стандартных методов решения линейных уравнений. Чтобы взломать такую защиту, злоумышленнику пришлось бы найти кратчайший вектор в многомерной решётке — а это NP-трудная задача.

Помимо решёток, рассматриваются и другие методы защиты: криптография на основе хеш-функций и кодовая криптография. Криптография на основе хеш-функций использует деревья Меркла для создания цифровых подписей. Стойкость здесь зависит только от надёжности самой хеш-функции, а не от сложности теоретико-числовых задач. Это делает такие системы очень предсказуемыми и безопасными.
